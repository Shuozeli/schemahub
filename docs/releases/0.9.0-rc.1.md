# SchemaHub {{SCHEMAHUB_VERSION}}

This is the first public release candidate for SchemaHub's human-and-agent
schema collaboration and immutable serving contract.

## Upgrade contract

- Source version: No prior published SchemaHub release.
- Target version: `{{SCHEMAHUB_VERSION}}`.
- Migration set: the embedded PostgreSQL baseline
  `202607210001_initial_schema.sql` and the versioned redb object encodings in
  this candidate.
- Mixed-version allowance: none. Stop the prior SchemaHub process before
  starting this candidate against its database, and do not run different
  SchemaHub versions against one redb file or PostgreSQL schema concurrently.
- Rollback window: retain the pre-deployment redb/PostgreSQL backup and the
  previously deployed image until candidate acceptance finishes. Database
  rollback is restore-based; do not delete SQLx migration ledger rows or run
  destructive down migrations on the live database.

## Compatibility changes

- This candidate establishes `schemahub.v1` gRPC/protobuf as the intended
  public 1.0 API. The unversioned `/api/*` routes are a GUI-only BFF supported
  with the bundled GUI from this same release.
- Applied change intent, reviews, compatibility results, conflicts, commits,
  operations, immutable revisions, and first-materialized artifacts are now
  durable resources.
- Protobuf, FlatBuffers, and the selected OpenAPI capability matrix are the
  supported 1.0 schema-format boundary. See `compatibility-policy.md` in the
  native archive for its exact guarantees.

## Known issues

- This is a prerelease. Promotion to 1.0 still requires the documented staging
  identity-provider drill, backup/restore evidence, and cross-candidate
  byte-for-byte artifact comparison.
- Supported external OpenAPI component refs are live/unpinned textual edges.
  Durable consumers must retain the resolved `SchemaRevision` and artifact
  digest; network URLs, arbitrary fragments, repository-root escapes, `$ref`
  siblings, and unsupported standalone reference shapes are rejected.
- SchemaHub stores and serves schemas and generated artifacts; it does not
  store application records or execute database migrations derived from user
  schemas.
