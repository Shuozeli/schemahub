# SchemaHub GUI BFF and Operational HTTP Interfaces

SchemaHub generates an OpenAPI 3.1 contract for the co-located HTTP interfaces
used by the web console and operators. It is the machine-readable authority for
the exact server build's paths, parameters, request bodies, response DTOs,
operation IDs, and bearer authentication metadata.

It is not a public REST v1 contract. The compatibility boundary accepted in
ADR 0002 is:

| Surface | Classification | Compatibility |
|---|---|---|
| `schemahub.v1` gRPC/protobuf | Public 1.0 API | Stable under the 1.x semantic-versioning policy |
| Unversioned `/api/*` HTTP/JSON | GUI-only BFF | Excluded from the public API promise; supported with the same-release GUI |
| `/healthz`, `/readyz`, `/metrics` | Operational | Supported under the operations policy |

Core authorization, audit, idempotency, publication, and immutable-serving
invariants apply regardless of transport. Classification changes compatibility
scope, not safety policy.

## Obtain the Contract

From a running HTTP listener:

```bash
export TAILSCALE_HOST="$(tailscale status --json | jq -r '.Self.DNSName' | sed 's/\.$//')"
curl -fsS "http://${TAILSCALE_HOST}:8080/api/openapi.json" | jq .
```

From the exact server binary without loading configuration, opening storage,
or starting a listener:

```bash
schemahub-server --print-openapi > schemahub-http-openapi.json
```

Every native release archive also contains `schemahub-http-openapi.json`,
generated by the packaged server after its release-tag version has been
embedded. Its `info.version` therefore matches `schemahub-server --version`,
health payloads, metrics, and archive metadata. That value identifies the exact
build; it is not a REST API stability version.

## Generation and Drift Control

HTTP DTOs and handlers in `crates/schemahub-server/src/http.rs` carry
`utoipa` schema and operation metadata. `http/openapi.rs` registers ordinary
runtime routes through `utoipa-axum`, collecting the same handlers into the
document rather than maintaining a separate handwritten route list.

Axum 0.7 uses catch-all routes for slash-preserving schema paths, while an
OpenAPI path parameter is represented as `{schema_path}`. The schema-detail
and immutable-artifact routes are the only explicit registration exceptions;
their annotated operations are merged into the generated document beside the
runtime `*schema_path` routes. Release-mode integration coverage verifies the
22 current path templates, both methods on the ChangeRecord collection, the
catch-all artifact operation, bearer security metadata, build version, and the
ChangeRecord external-reference schema. It also verifies the boundary metadata:

- document info names `schemahub.v1` as the public API and `/api/` as the BFF
  prefix;
- every `/api/*` path has `x-schemahub-api-surface: gui-bff` and
  `x-schemahub-compatibility-promise: excluded`;
- operational paths have `x-schemahub-api-surface: operations` and
  `x-schemahub-compatibility-promise: supported`.

Every runtime `/api/*` response, including errors, additionally carries
`x-schemahub-api-surface: gui-bff`. Operational responses deliberately omit
that BFF header. Cross-origin deployments expose the header through CORS.

## Authentication

The document defines `bearerAuth` as HTTP bearer authentication and makes it
optional at the document level because authentication is deployment-specific:

- noop development deployments accept anonymous requests;
- static-token deployments accept configured opaque bearer tokens;
- production JWT deployments validate signed tokens against the configured
  issuer, audience, token type, algorithms, and rotating JWKS.

Operational routes and OpenAPI discovery do not consume caller identity.
Resource authorization is still enforced by Core for every project/repository
operation; the OpenAPI setting is not an authorization bypass.
If an Authorization header is present but is not valid ASCII, the BFF returns
`401` and never retries the request as anonymous. An empty ChangeRecord target
is resolved to the repository's configured default bookmark before the durable
record is created.

## Responses and Cache Behavior

Application errors use `{"error":"..."}` JSON. Axum extractor failures such
as malformed query/path values or an oversized/malformed JSON body can return
plain text before a handler executes, so generated default responses advertise
both media types. Immutable artifact responses additionally document `304`
cache validation; the serving contract and digest headers are detailed in
`serving.md`.

`/api/openapi.json` is generated entirely from compile-time metadata and is
served with `Cache-Control: public, max-age=3600`. Restarting the same binary
does not change the document.

## Public REST in the Future

The 1.0 boundary decision is complete: `/api/*` remains a GUI-only BFF. A
future public REST API must use a versioned prefix such as `/v1/`, follow the
accepted resource and method conventions, ship a separately identified
OpenAPI contract, and receive an explicit compatibility declaration. It cannot
silently promote or alias the current convenience routes. See
`ADR/0002-public-api-and-gui-bff-boundary.md` and
`compatibility-policy.md`.
